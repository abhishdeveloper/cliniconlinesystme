## 2024-05-15 - Bulk SQLite Inserts and N+1 Read Overhead
**Learning:** SQLite disk I/O overhead per query/transaction is severe, especially in local development environments. Generating a large number of appointment slots sequentially led to an N+1 query pattern where each slot verification and insertion was an independent transaction. Fetching all potential candidate rows in a single batch (via `BETWEEN` and array map lookups) and combining all inserts inside a single `$pdo->beginTransaction()` reduced total generation time by over 99%.
**Action:** When handling bulk inserts or checking existence against a large set of conditions in SQLite (and MySQL), always prefer batched `IN`/`BETWEEN` queries to retrieve state into application memory. And crucially, wrap bulk data modification in an explicit transaction (`$pdo->beginTransaction()` and `$pdo->commit()`) to avoid individual disk synchronization per row.
