## 2024-05-24 - N+1 Queries and SQLite Transaction Bottlenecks during Batch Inserts
**Learning:** Performing multiple individual `SELECT` queries to check existence and then executing individual `INSERT` statements inside nested loops (N+1 query problem) creates massive overhead. This is especially problematic in SQLite, where each un-transactional insert triggers expensive disk-sync I/O operations, leading to severe performance degradation during bulk generation tasks like scheduling.
**Action:** Always fetch existing records in a single upfront query and map them into an O(1) in-memory hash map (e.g., using `array_flip(PDO::FETCH_COLUMN)` in PHP). For bulk inserts, always wrap them in a single database transaction (`$pdo->beginTransaction()` and `$pdo->commit()`) to avoid individual disk synchronization per row.
