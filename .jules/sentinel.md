## 2024-03-14 - Fix Insecure GET Request and CSRF for State Changes
**Vulnerability:** A critical security flaw was identified where state-altering actions (e.g., deleting a medicine) were performed via insecure HTTP `GET` requests (`?delete=ID`) without CSRF token protection. This allowed Cross-Site Request Forgery (CSRF) attacks, where an attacker could construct malicious links that silently execute actions if a privileged user is authenticated. Additionally, state-changing POST forms lacked CSRF tokens.
**Learning:** Performing state modifications using `GET` requests violates standard HTTP semantics and makes the application highly vulnerable. It bypassing standard same-origin policy checks for forms, thus making attacks trivial to execute via image tags or links.
**Prevention:** All state-altering operations must use POST requests and implement CSRF token validation. Forms should generate an unpredictable token tied to the user's session, which the server verifies before fulfilling the request. Helper functions like `generateCsrfToken()` and `validateCsrfToken()` must be consistently used across all state-changing endpoints.
